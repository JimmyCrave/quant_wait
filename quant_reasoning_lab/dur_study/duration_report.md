# 校正时长定向验证：审计报告 + BF16 校正时长实验

模型 DeepSeek-R1-Distill-Qwen-1.5B；AWQ3 = W3 g128 **数值模拟**（反量化后 bf16 存储，不是真 3-bit kernel，不做速度/显存结论）。
证据等级：**[观察]** 描述；**[反事实]** 同前缀配对；**[干预]** 同前缀的窗口干预；**[描述·有选择偏差]** 以事后条件定义的子集；**[未验证]**。
所有路径相对 `quant_reasoning_lab/`；复现命令 `dur_study/reproduce_dur.sh`。

## 0. 结论（先读这里）

1. **实现与前缀没有问题，实验可解释。** 同批前缀上全程 BF16 明显优于 AWQ3（4096 内完成最终答案且正确：0.79 vs 0.24，配对差 +0.55，CI [0.43, 0.68]）。切换一致性的结构检查全部通过（12 项硬性检查 + 2 项信息项）。
2. **校正时长—收益是强烈单调的，32 与 256 token 不足，1024 token 才出现大幅收益。** 相对全程 AWQ3 的配对差：W32 +0.03 [−0.05, 0.13]；W256 +0.09 [0.01, 0.19]；W1024 +0.35 [0.22, 0.50]；全程 BF16 +0.55；AWQ3 + 全程 marker penalty +0.29 [0.16, 0.43]。
3. **W1024 的收益里有一半以上不是"切回后保留"。** 96 次里 25 次（26%）是 BF16 在窗口内直接把整个回答写完并 EOS（全部正确）；切回 AWQ3 后才完成并正确的是 32 次（33%）。W1024 仍比全程 BF16 低 0.20 [0.10, 0.30]，说明切回后一部分改善丢失。
4. **"切回后改善是否保留"的答案：部分保留，证据只是描述性的，不能写成"修复效果保留"。** 在"窗口内没写完"的子集里（有选择偏差），W1024 切回后完成并正确 45%（n=71，29 个锚点），而全程 AWQ3 在"前 1024 token 内没完成"这一同样条件下只有 18%（n=88），全程 BF16 同条件下 74%（n=78）。条件子集由结局定义，不是随机分配，只能说"没有看到完全回落到 AWQ3 水平"。
5. **总体归类：窗口不足（≤256 token 无效或证据不足）+ 改善部分保留 + 前缀依赖明显**（19/32 个锚点在全程 AWQ3 下 0 次成功；W1024 把这个数降到 6，全程 BF16 降到 4）。这并不支持"损伤只在几十个 token 的局部 logit 错误"，但也不能区分"需要足够长的 BF16 推理才能走出循环/完成"与"持续性倾向变化"。
6. **审计发现两个会影响第一、二阶段表述的问题**（见 §1）：(a) 第一阶段评分器对未结束的轨迹宽松给分，AWQ3 的"准确率"被高估约 15 个百分点；(b) 论文 marker 惩罚不覆盖无前导空格的变体（如行首 `Wait`），在 AWQ3 轨迹里这类变体的频率高于被惩罚的 49 个 token。人工盲审**未完成**。

## 1. 第一阶段：实现与统计审计

### 1.1 预算耗尽但被判对的轨迹（`audit/audit1_*.csv`）[观察]
把"评分器判对 / 结束思考（出现 `</think>`）/ 完成最终答案（`</think>` 之后有闭合的 `\boxed{}`）/ 最终答案正确"四件事分开，覆盖 BF16、AWQ3 各 400 条轨迹（种子 42–45）和 AWQ3+penalty 100 条。

| 配置 | 评分器准确率 | 严格准确率（`</think>` 后完整且正确） | 预算耗尽 | 评分器判对但没结束思考 |
|---|---|---|---|---|
| BF16 (400) | 0.805 | 0.805 | 15 | 0 |
| AWQ3 (400) | 0.405 | **0.255** | 268 | **60**（其中 53 条预算耗尽、7 条 EOS 但没写 `</think>`） |
| AWQ3+λ1（种子 42，100） | 0.51 | 0.47 | 35 | 4 |

* 预算耗尽且评分器判对的 AWQ3 轨迹共 53 条：**53 条全部没有 `</think>`**，51 条在思考文本里连 `\boxed` 都没有。评分器（`ExprExtractionConfig` + `\boxed` 优先，`aggregation=max`）从未结束的思考文本里抽取数值/表达式，只要任一候选与标准答案相符就给分。其中约一半的"正确"，仅凭文本里最后出现的数字就能复现，说明是偶然命中。
* 影响：AWQ3 的"准确率 0.405"应改为严格口径 **0.255**；λ=1 的收益在严格口径下更大：种子 42 上 +0.26（SE 0.048），评分器口径仅 +0.12（SE 0.046）。BF16 不受影响。
* 不受影响的结论：B3/B5 的结局（`correct_by_end` 要求 `</think>` 后再判对）和本阶段的主要终点本来就是严格口径。受影响的是第一阶段汇总表、B2 里的 `accuracy`、`frac_reached_correct_final_score1` 等直接用评分器分数的列。

### 1.2 组均值之差与配对差为什么不一致（`audit/audit2_*.csv`）[观察]
* B3 表里 BF16/AWQ3 两列是**按前缀平均**（每个前缀内先平均 3 个种子）；差值列是**按题目加权**（先在每个题内平均配对差，再对 28–29 个题平均，bootstrap 也按题重抽）。32 个前缀分属 28–29 个题，每题 1–2 个前缀，所以两个口径不同。
* 数值对账：CA 提交率前缀加权差 −0.604，报告的题目加权差 −0.580；CA 提交且正确 −0.583 vs −0.563；G 提交 −0.583 vs −0.589；L 脱离 −0.333 vs −0.345；G 进入循环 +0.208 vs +0.208。最大偏差 0.024，方向和显著性不变。到提交的受限平均 token：+1660 vs +1593。
* B5 不存在这个问题：每题每族只有一个锚点，加权口径一致；报告里各列用的是同一批 48（V 族 24）个锚点（`audit2_b5_mean_vs_paired.csv` 逐项对账为 0 差）。
* 建议：以后表里差值列用"各列均值的差"或明确标注"按题加权"。

### 1.3 49 个 marker 与论文 50 个条目（`audit/audit3_*.csv`）[观察]
* 论文附录 C 表 8 的 50 个条目全部带前导空格（`_perhaps … _incorrect`）。逐条核对 Qwen tokenizer：**49 个是单 token 且 id 回转一致；`_recheck` 被切成 `Ġre`+`check`**，按"绝不猜 id"的规则排除。`_recheck` 在 800 条轨迹里只出现 13 次，影响可忽略。映射不含任何第三方插件的 GLM id。
* **覆盖缺口（论文方法本身的性质，不是实现错误）：** 无前导空格的变体不会被惩罚。每千个思考 token 的频率：被惩罚的 49 个 token 合计 BF16 12.7 / AWQ3 26.3；34 个无空格变体合计 BF16 9.6 / AWQ3 **35.7**，其中行首 `Wait` 一项 AWQ3 为 33.9（BF16 5.1）而 ` Wait` 只有 6.7（BF16 0.56）。论文自己的高 KL 列表也含无空格的 `Wait`/`But`/`Alternatively`。
* 含义：AWQ3 的"重新检查"类 token 大部分出现在段落开头，λ=1 惩罚碰不到。全程 penalty 的收益机制因此更不清楚（可能经由被惩罚的 ` Wait`/` but` 间接起作用）。**未做**：把无空格变体加进惩罚的实验。

### 1.4 干预总新增预算是否包含 BF16 窗口（`audit/audit4_*.csv`）[观察]
按原始请求/响应文件逐条核对 B5 的 3438 个分支：阶段二 `max_tokens = 4096 − 窗口长度`（全部满足），所有分支新增 token（窗口 + 切回后）≤ 4096，0 个违规；阶段二 prompt 与"阶段一 prompt + 窗口 token id"逐 token 完全一致（0 个违规）。**窗口在 4096 预算内。** BF16 的前缀 prefill（约 3k token）不在 4096 内，单独计入成本表。

### 1.5 切换一致性验证（`audit/audit5_*.csv`，`src/b7_consistency.py`）
**结构检查（12 项硬性检查全部通过，另有 2 项信息项）：**
* 提示 = 第一阶段评测提示：100 题的 token id 与第一阶段 `full_prompt` 的分词逐个相同，长度等于 `num_input_tokens`；32 个锚点的 prompt+前缀中 BOS / `<｜User｜>` / `<｜Assistant｜>` / `<think>` 各恰好 1 个，没有 `</think>` 或 EOS（**没有重复加 chat template**）。
* 锚点前缀 = 原始采样 token id（`generated_token_ids[:start]`），没有重新分词；切换时以 token id 直接拼接，不经 decode→encode。
* 2256 次合并运行：EOS 只出现在末尾，`stop` ⇔ 末尾是 EOS（**没有丢失/多余终止符**）；窗口以 EOS 结束的 30 次没有被续接；窗口 token 是合并输出的精确前缀；总长度不超过 T。
* 重新分词仅用于循环检测的分段，不进入生成；decode→encode 往返一致比例见 `audit5_structural_checks.csv`。
* 不应重置的状态：采样参数（T=0.6, top-p=0.95）在所有阶段一致，没有重复/频率惩罚、没有 `min_tokens`；marker processor 只在 DP 组且无状态；唯一"重置"的是随机流：阶段二用 seed+100，这在分布意义上不重要。

**同种子诊断：** 相同模型相同种子，切换运行阶段一的前 W 个 token 与不切换运行的前 W 个只有 0–7% 完全相同，LCP 中位数 2。诊断（`audit/seed_repro_*.txt`）：同一请求单独跑两次 128 token 逐位相同；`max_tokens` 不影响；**放进不同批次/不同批内顺序就会分叉**（有的从第 0 个 token 开始，bf16 在批次不同时 prefill/注意力数值不同）。所以种子不能当作跨分支的共同随机数，所有比较只能是分布比较——与要求一致。

**分布比较（8 种子 × 32 锚点，T=2048，按锚点聚类 bootstrap；`audit5_distribution_comparison.csv`）：**

| 比较 | primary Δ [95% CI] | 结束思考 Δ | 重复 Δ |
|---|---|---|---|
| AWQ→AWQ W32 − 无切换 | +0.008 [−0.023, 0.039] | −0.031 [−0.074, 0.008] | −0.016 [−0.078, 0.039] |
| AWQ→AWQ W256 − 无切换 | **+0.047 [0.004, 0.094]** | +0.043 [−0.004, 0.090] | +0.012 [−0.031, 0.055] |
| BF16→BF16 W32 − 无切换 | 0.000 [−0.059, 0.062] | 0.000 [−0.047, 0.047] | 0.000 [−0.016, 0.020] |
| BF16→BF16 W256 − 无切换 | −0.020 [−0.078, 0.039] | **−0.062 [−0.121, −0.004]** | +0.012 [−0.012, 0.043] |

## 2. 第二阶段：校正时长实验

### 设计（选择前未读取任何干预结果）
* 锚点：B5 的 A 族 48 个锚点（AWQ3 自己生成、首次提出正确答案之后的位置，每题 1 个）。可用条件：原始采样 token id 已保存且重新分词前缀与其完全相同 → 36 个符合；按 `sha1("dur-A-v1|"+anchor_id)` 取最小的 **32 个**。选择记录 `data/anchor_selection.jsonl`。
* 长预算子集：这 32 个中按 `sha1("dur-T8192-v1|"+id)` 最小的 **8 个**（第一稿用 hash%4 得到 17 个，不算小子集，在任何生成之前改为 8 个）。
* 6 组 × 3 种子（1,2,3），总新增预算 4096（含窗口）：**D0** 全程 AWQ3；**W32/W256/W1024** BF16 窗口后切回 AWQ3（窗口以 EOS 结束则不续接）；**DB** 剩余全程 BF16；**DP** 全程 AWQ3+marker penalty（λ=1）。
* 主要终点：4096 内 `</think>` 后出现闭合 `\boxed{}` **且**最后一个 `\boxed` 判对（第一阶段评分器，只对 `</think>` 之后的文本）。次要：结束思考、逐字重复（检测器，沿用 `det` 定义）、到答案完成的 token 数。
* 统计：每个锚点内先平均 3 个种子，对 32 个锚点（= 32 个题）配对、bootstrap 5000 次。

## 3. 局限与未验证
* 32 个锚点、每个 3 个种子；CI 很宽（W256 与 W1024 的 CI 与 DB 的 CI 部分重叠）。多个终点、多个组间比较，未做多重比较校正。
* 锚点都来自 AWQ3 自己的、已经提出正确答案的轨迹，且是 36 个可用锚点中按 hash 选的 32 个；结论对其他前缀分布（如循环中、未提出答案）不一定成立。
* 逐字重复用 `det` 检测器（事后加入的、不依赖标注器的定义）；没有人工复核，没有 labeler 对续写的状态标注。
* 窗口时长只测了 32/256/1024；没有测 512、2048、"到答案完成为止"这种自适应窗口，也没有测 KV 单独替换。W256 受 §1.5 的切换伪影上界限制不可解读。
* W1024 的增益里 26% 是 BF16 直接写完；这是真实的"窗口内完成"，但不能算切回后的保留。
* 种子不是共同随机数；GPU bf16 采样不保证逐位复现。
* 人工盲审未完成（0/60）。
* 第一阶段和 `mechanism_report.md` 中用评分器分数的数字需按 §1.1 修正（已在报告开头加勘误）。

## 4. 下一步最值得做的一项
在同一批 32 个锚点上做"到答案出现 / 到 `</think>` 为止的自适应 BF16 窗口"以及 512、2048 两个固定长度，分开计算 BF16 窗口内完成与切回后完成，并先把 `Wait`/`But`/`Alternatively` 等无空格变体并入 penalty 作为 DP 的对照；同时让 2 位以上标注者完成 60 窗口的盲审，以便把重复检测器的精度定标。
